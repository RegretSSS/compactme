# Compact Me — 模型自压缩与自唤醒

## 原理

`/compact` 是 TUI 命令，模型没有官方通道触发。本插件的 `compactme` 工具通过
`$TMUX_PANE` 定位自己所在的 tmux pane，由**后台 watcher**（每 pane 一个独立进程，
多实体互不冲突）完成**事件驱动的两段注入**：

1. 等待 settle（模型写完收尾总结、TUI 回到输入态）→ 分键注入 `/compact <描述>`
   （文本先进框，Enter 独立后发，防时序竞争）
2. 通过 **PreCompact / PostCompact hook 标记**（插件自注册，写
   `/tmp/compactme/hooks/`）确认压缩开始/完成；hook 未生效时降级为
   **session transcript** 的 `isCompactSummary` 判据（v0.3 信号源，不再看屏幕
   ——v0.2.x 四次生产事故全是屏幕形态问题）。压缩确认完成后**才**注入
   `<唤醒词>`——post-compact 动态注入

若 `/compact` 被当成普通消息吞掉（PreCompact 不触发），watcher 超时后自动
重试（≤2 次）；全局超时则兜底注入唤醒词（含重建线索，晚到无损）。

**只发第一条 = 自杀**：压缩后的新上下文停在待机态，无法自我恢复任务。
第二条唤醒词是活的唯一保证。

## 触发水位（绝对 token，不看窗口占比）

质量衰减随**绝对 token 量**发生，不随窗口占比：1M 窗口的 70% 是 700K，
那时注意力早已涣散；200K 窗口的 70% 只有 140K，又太松。占比阈值两头都错。

满足以下任一条件，模型应主动发起压缩（调用 `context_stats()` 核实水位）：

| 档位 | 条件 | 动作 |
|---|---|---|
| **hard** | 上下文 ≥ **400K** tokens | 无条件压缩。立即落盘重建线索，走调用流程 |
| **soft** | 上下文 ≥ **200K** 且工作处于**明显天然断点**（阶段完成、任务收尾、plan 刚产出） | 在断点处压缩，避免拖到 hard 档才在任务中途动刀 |
| **reserve** | 后续工作为核心改动（架构决策、关键算法、易错重构），当前上下文已明显冗余 | 模型自行判断，主动整理以提高工作质量 |

断点判定的意义：soft 档压缩的代价最小——摘要正好接在阶段性结论之后，
重建线索（plan/TaskList）恰好新鲜。错过断点再压，摘要就得切割未完成的工作。

## 可用时机（必须命中其一，且重建线索已落盘）

| # | 时机 | 落盘要求 |
|---|------|----------|
| 1 | **有 Plan 文本** — plan mode 产出的计划已成形 | 计划全文已写入文件（`plans/`、`PLAN.md` 等），路径确定可读 |
| 2 | **明确 task 追踪** — 任务有结构化追踪 | TaskList 有未完成任务，或任务清单已写入文件 |
| 3 | **其他线索指向型文档落盘** — CLAUDE.md、MEMORY.md、HANDOFF.md、TODO.md 等已包含当前任务状态与下一步 | 文件路径确定可读 |
| 4 | **紧急情况** — 检测到自己复读（重复同样的工具调用/结论）或注意力漂移（答非所问、丢失目标） | **先立即**把当前任务状态写入文件，再压缩 |

四类时机的共同前提：**任务状态在磁盘上，不只在对话里**。
没有任何落盘线索时禁止调用——先落盘，再压缩。

## 调用流程（顺序不可换）

1. **落盘**：更新 Plan 文件 / TaskList / HANDOFF，确保新上下文有东西可读
2. **收尾总结**：给用户一段清晰的进度总结（它会进入压缩摘要，等于给下一个自己留的遗书）
3. **最后一个工具调用** `compactme(compact_instructions, wakeup_word, settle_seconds)`，
   然后结束回合。watcher 默认等 6s settle——收尾总结要在这个窗口内写完；
   预计要写很长就调大 `settle_seconds`

## 唤醒词必须包含任务重建线索

唤醒词（第二组消息）必须写明三件事，缺一会被工具拒绝：

- **去哪读**：具体文件路径，或 TaskList
- **读什么**：文件里的哪个部分是当前任务状态
- **怎么续**：下一步的第一个具体动作

模板：

> compact 已结束。任务重建：读取 `/path/to/PLAN.md` 的「实施步骤」一节与 TaskList，恢复任务追踪，从「<下一个具体动作>」继续。上下文已压缩，先重读文件再动手，不要凭记忆臆测。

`compact_instructions`（第一组消息）侧重"保留什么"：当前任务状态、已完成步骤、
关键决策、相关文件路径。唤醒词会自动冗余预告进描述里，双保险。

## 不可用的时机

- 任务只存在于对话中，无任何落盘线索 → 先落盘
- 用户输入框可能有未提交草稿 → 不要调用
- 有长时间后台任务在跑 → 等任务落地、结果落盘后再压
- 不在 tmux 里运行 → 工具会直接报错
