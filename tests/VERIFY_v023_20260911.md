## v0.2.4（2026-09-12/13 修复，13 单测 + e2e 4/4 全过）

### 事故：pane %2 `FAILED / wakeup unconfirmed`（非 0.2.2 老毛病）

- `/tmp/compactme/2/watcher.log`：两轮 `text landed=False` → FAILED。
  pane %2 已跑 v0.2.3（日志有 `text landed=` 格式），走的是诚实失败路径。
- 根因：Compacted 后固定 sleep 1s 即注入 + 轮间隔仅 0.5s，全撞在压缩后
  TUI 摘要渲染忙期（实证：idle 后注入 727 字符 0.15s 即落地——机制无碍，
  纯时序）；当时无现场 dump，只能推断。

### 修复（用户观察驱动的协议重构）

1. **❯ 判据替代 busy**（用户提出「用户发言灰底渲染」）：成功 = 全屏最后
   一条 `❯ +普通空格` 用户消息含唤醒词 head 且非 `/compact` 前缀。
   字节级实测：**输入框行 = ❯+nbsp(\xa0)，已提交消息 = ❯+普通空格**——
   这是「文本在框」vs「已发出」的可靠区分，不依赖行区域划分
   （压缩刚完成时消息流只有几行，新消息会落进底部 N 行窗口，按区域判必错，
   e2e 实战撞出双发后才修全屏搜）。
2. **BSpace×1200 清框**：C-u 实测无清行语义（727 字符注入后 C-u 原样不动）。
3. **轮前退避 0/3/8s 共 3 轮** + 落地失败 dump 屏幕底部 10 行留痕。
4. split_screen 只删 split artifact 保留真实空行（rstrip 会吃空行致窗口错位）。

### e2e 调试中撞出并修复的坑（fake 保真度）

- fake 输入框折行渲染（v2 的横向滚动模型是错的）+ **底部锚定布局**
  （顶部锚定会让「底部 N 行=输入区」取到空行）
- tmux `new-session -x -y` 会被 attached client 尺寸覆盖（179x50），
  fake 用 ioctl 实际值
- 短唤醒词不折行时 ❯+nbsp 与 tail 同行——in_input 不能排除 ❯ 开头行
  （只能按 nbsp/空格前缀区分）
